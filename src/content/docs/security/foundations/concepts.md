ก่อนจะไปเจาะระบบหรือป้องกันอะไร ต้องเข้าใจ "ภาษา" และ "แนวคิด" พื้นฐานของ security ก่อน หน้านี้คือรากฐานทั้งหมด

---

## 1. CIA Triad — หัวใจของ Security

ทุกอย่างใน security วนอยู่รอบ 3 คำนี้:

| ตัวย่อ | ชื่อ | หมายความว่า | ตัวอย่างเมื่อถูกละเมิด |
|---|---|---|---|
| **C** | Confidentiality (ความลับ) | ข้อมูลเข้าถึงได้เฉพาะคนที่มีสิทธิ์ | ข้อมูลลูกค้ารั่วไหล |
| **I** | Integrity (ความถูกต้อง) | ข้อมูลไม่ถูกแก้ไขโดยไม่ได้รับอนุญาต | โจรแก้ยอดเงินในบัญชี |
| **A** | Availability (ความพร้อมใช้) | ระบบใช้งานได้เมื่อต้องการ | เว็บล่มเพราะโดน DDoS |

:::note
เวลาออกแบบระบบหรือประเมินความเสี่ยง ให้ถามตัวเองเสมอว่า "ภัยนี้กระทบ C, I หรือ A?"
:::

## 2. คำศัพท์ที่สับสนบ่อย

คนเริ่มต้นมักใช้คำพวกนี้ปนกัน — จำให้แม่น:

```
Threat (ภัยคุกคาม)      = สิ่งที่อาจทำอันตราย เช่น hacker, มัลแวร์, ไฟไหม้
Vulnerability (ช่องโหว่) = จุดอ่อนในระบบ เช่น software เก่า, รหัสผ่านอ่อน
Exploit                 = เทคนิค/โค้ดที่ใช้ "ยิง" ผ่านช่องโหว่
Risk (ความเสี่ยง)        = โอกาสที่ threat จะใช้ vulnerability ทำให้เกิดความเสียหาย
```

**สูตรจำง่าย:**

```
Risk = Threat × Vulnerability × Impact
```

> ตัวอย่าง: มี hacker (threat) + เว็บใช้ library เก่ามีช่องโหว่ (vulnerability) + เก็บข้อมูลบัตรเครดิต (impact สูง) = **risk สูงมาก**

---

## 3. Attack Surface (พื้นที่โจมตี)

**Attack surface** = ทุก "ทาง" ที่ผู้โจมตีเข้ามาได้ เช่น port ที่เปิด, form รับ input, API, พนักงาน (social engineering)

หลักการสำคัญ → **ลด attack surface ให้เล็กที่สุด**
- ปิด port/service ที่ไม่ใช้
- ลบ account/สิทธิ์ที่ไม่จำเป็น
- อย่าเปิดเผยข้อมูลระบบเกินจำเป็น

---

## 4. Defense in Depth (ป้องกันหลายชั้น)

อย่าพึ่งการป้องกันชั้นเดียว — วางหลายชั้นซ้อนกัน เหมือนปราสาทที่มีทั้งคูน้ำ กำแพง และประตู

```
[ Network firewall ]
   [ WAF ]
      [ Authentication ]
         [ Least privilege ]
            [ Encryption ]
               [ 🗄️ data ]
```

ถ้าชั้นนึงพลาด ยังมีชั้นถัดไปกันไว้

---

## 5. หลักการสำคัญที่ต้องจำ

- **Least Privilege** — ให้สิทธิ์เท่าที่จำเป็นเท่านั้น (user, service, container)
- **Fail Securely** — เมื่อระบบพัง ต้องพังในสถานะที่ปลอดภัย (default = deny)
- **Zero Trust** — ไม่เชื่อใครโดยอัตโนมัติ ตรวจสอบทุกครั้ง แม้อยู่ใน network เดียวกัน
- **Shift Left** — ตรวจ security ตั้งแต่ต้นทาง (ตอน dev) ถูกและง่ายกว่าเจอตอนหลัง

---

## 6. Attacker Mindset — คิดแบบคนโจมตี

การป้องกันที่ดีเริ่มจากการเข้าใจว่าคนโจมตีคิดยังไง เวลาเจอระบบให้ลองถาม:

- ข้อมูลนี้ใครได้ประโยชน์ถ้าขโมยไป?
- input ตรงนี้ถ้าใส่อะไรแปลกๆ จะเกิดอะไร?
- ถ้าเป็นฉันจะเข้าทางไหนง่ายสุด?

:::caution[White Hat เท่านั้น]
เราเรียน offensive เพื่อ **ป้องกัน** ทดสอบเฉพาะระบบของตัวเองหรือที่ได้รับอนุญาตเท่านั้น — นี่คือเส้นแบ่งระหว่าง security researcher กับอาชญากร
:::

---

## 7. พื้นฐานที่ต้องมีก่อนไปต่อ

Security ตั้งอยู่บนความเข้าใจระบบ ถ้ายังไม่แน่น 2 อย่างนี้ กลับไปทบทวนก่อน:

- **Linux** — command line, permission, process → ดู [Linux track](/linux/basics)
- **Networking** — TCP/IP, port, DNS, HTTP/HTTPS, การทำงานของ request-response
